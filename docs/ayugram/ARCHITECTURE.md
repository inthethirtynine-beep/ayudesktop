# Архитектура AyuGram Desktop

Документ описывает архитектуру кодовой базы AyuGram Desktop (форка Telegram Desktop / `tdesktop`), ключевые подсистемы, стандарты разработки и правила расширения функционала.

---

## 1. Обзор проекта и технологический стек

* **Язык**: C++20 (MSVC на Windows, Clang на macOS/Linux).
* **GUI-фреймворк**: Qt (кастомные виджеты и стили поверх Qt Core/Gui/Widgets).
* **Система сборки**: CMake (`tdesktop/CMakeLists.txt`) с модулями `cmake_helpers`.
* **Сетевой протокол**: MTProto 2.0 (собственная реализация Telegram Desktop).
* **Реактивное программирование**: Библиотека `rpl` (Reactive Programming Library).
* **Многопоточность / шедулинг**: Библиотека `crl` (C++ Reactive Library).
* **Локальная база данных**: SQLite / sqlite_orm (для истории сообщений и настроек AyuGram).

## 3. Архитектура подсистем AyuGram (`Telegram/SourceFiles/ayu/`)

AyuGram расширяет Telegram Desktop следующими компонентами:
1. **`ayu/ayu_settings.h / .cpp`**: Настройки приватности и кастомизации (Ghost mode, сокрытие онлайна, заморозка последнего захода, стример-мод, локальный Premium).
2. **`ayu/ayu_state.h / .cpp`**: Глобальное состояние AyuGram в runtime.
3. **`ayu/ayu_worker.h / .cpp`**: Фоновый воркер для асинхронных операций.
4. **`ayu/data/ayu_database.h / .cpp`**: Локальная SQLite база данных для сохранения удалённых и отредактированных сообщений, медиа и истории.
5. **`ayu/ui/settings/settings_ayu.h / .cpp`**: UI страницы настроек AyuGram в основном меню настроек.
6. **`ayu/features/`**: Отдельные фичи:
   - `forward/`: Пересылка без автора / цитирования (`ayu_forward.h`).
   - `translator/`: Встроенный переводчик через внешние провайдеры.

## 4. Гайдлайны по разработке и C++ стилю

### 4.1. Комментарии и документация кода
* Комментарии должны быть краткими: одна строка, поясняющая **зачем** (WHY), а не **что** делает код.
* Не удалять существующие комментарии проекта без веской причины.

### 4.2. Использование типов и синтаксиса
* **`auto`**: Предпочитать `auto`, `const auto &` вместо громоздких явных типов (особенно для итераторов, продюсеров `rpl` и временных объектов).
* **Строковые литералы**: Использовать `u"текст"_q` вместо `QStringLiteral("текст")`.
* **Запрет кастов подавления**: Запрещены `static_cast<void>(...)` и `(void)expr`. Если функция помечена `[[nodiscard]]`, результат должен обрабатываться должным образом.
* **Платформенные проверки**: Telegram Desktop делит платформы на Windows, macOS и "all-other" (Linux/BSD). Не использовать `Q_OS_LINUX` для общих Unix-веток, использовать `!defined Q_OS_WIN && !defined Q_OS_MAC` или `Platform::IsLinux()`.

## 5. Работа с сетью и Telegram API (MTProto)

1. **Схемы API**:
   - `Telegram/SourceFiles/mtproto/scheme/api.tl` — схема методов и типов Telegram API.
   - `Telegram/SourceFiles/mtproto/scheme/mtproto.tl` — схема шифрования и транспорта.
2. **Отправка запросов**:
   - Использовать `api().request(...)` или собственный `MTP::Sender _api`.
   - Ответы приходят в колбэки `.done([...])` и `.fail([...])`.
3. **Управление временем жизни колбэков**:
   - Колбэки `api().request` принадлежат сессии и живут дольше виджетов.
   - **Всегда защищать контекст** вызова с помощью `crl::guard(this, [=](const auto &result) { ... })`.
   - Либо использовать `MTP::Sender`, который при уничтожении объекта автоматически отменяет незавершённые запросы.

## 6. Пользовательский интерфейс и стилизация

* **Файлы стилей `.style`**: Размеры, отступы, цвета и шрифты задаются в декларативных файлах `.style` (генерируются в C++ заголовки `style_*.h`).
* **Масштабирование**: Запрещено жестко прошивать константы пикселей (`48`, `12` и т.д.) в C++ коде для виджетов, так как это ломает масштабирование интерфейса (HiDPI). Все размеры берутся из `st::константа`.
* **Длительности анимаций**: Длительности анимаций не помещаются в `.style`, а объявляются как `constexpr auto kDuration = crl::time(150);` в анонимном пространстве имен `.cpp` файла.

## 7. Локализация

* Все пользовательские строки объявляются в `Telegram/Resources/langs/lang.strings`.
* Строки AyuGram размещаются в `Telegram/SourceFiles/ayu/ayu_lang.cpp / .h` или в общих строках.
* Использование:
  - Немедленное получение: `tr::lng_some_key(tr::now)`
  - Реактивное: `tr::lng_some_key()` (возвращает `rpl::producer<QString>`).

## 8. Реактивное программирование (RPL)

Telegram Desktop активно использует `rpl`:
* `rpl::producer<T>` — поток значений.
* `rpl::lifetime` — дескриптор времени жизни подписки. Подписка активна, пока жив lifetime.
* Трансформации: `| rpl::map(...)`, `| rpl::filter(...)`.
* Комбинации: `rpl::combine(...)`, `rpl::merge(...)`.
* При связывании виджетов продюсер передается в целевое свойство через lifetime виджета.
