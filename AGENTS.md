## 2. Основные правила разработки

1. **Изоляция кода AyuGram**:
   - Новые функции, экраны и структуры данных создаются в папке `Telegram/SourceFiles/ayu/`.
   - Изменения в базовых классах Telegram Desktop должны быть минимальными точечными хуками (seams), вызывающими функции модуля `ayu::`.
2. **Безопасность памяти и MTProto**:
   - Всегда оборачивайте колбэки сетевых запросов в `crl::guard(this, [=](...) { ... })` для предотвращения use-after-free, либо используйте `MTP::Sender`.
3. **Стили и масштабирование**:
   - Запрещено прописывать размеры и координаты пикселями в C++ коде. Все визуальные параметры задаются в `.style` файлах и используются через `st::имя`.
4. **Формат и стиль кода**:
   - Используйте `u"строка"_q` для `QString`, предпочитайте `auto` для сложных типов.
   - Комментарии краткие, объясняющие **зачем** (WHY), а не что делает код.
   - Текстовые файлы: кодировка UTF-8 без BOM, окончания строк CRLF (Windows).
5. **Сборка проекта**:
   - Не запускайте полную сборку Release без прямой просьбы пользователя (она чрезвычайно ресурсоёмкая). Используйте конфигурацию Debug.

* Заголовок коммита: краткий, до 50–60 символов, в едином стиле с `git log`.
